# flowstate Plan B2: Vibe Engine + Feedback + Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vibe-aware shuffle (lock/drift, mood chips, weighted-random variety, "doesn't fit" feedback) wired into the existing player, shipped as a signed release APK on GitHub Releases (v0.2.0-alpha).

**Architecture:** Pure-TS engine (`src/engine/`) with all math TDD'd offline; a `VibeQueue` implementing the existing `QueueSource` interface; SQLite feedback tables via the existing op-sqlite db; UI additions to the salvaged screens. NO on-device verification this plan (device unavailable) — gate is typecheck + jest + successful release build.

**Tech Stack:** existing app stack (RN 0.86, TS, op-sqlite, react-native-track-player, jest).

## Global Constraints

- Engine formulas are LOCKED by the v2 spec (docs/superpowers/specs/2026-07-22-flowstate-v2-design.md): weight = sim^4 × recency × feedbackBias; recency = min(1,(songsSince/25)^2); lock threshold 0.75, drift 0.65; pair penalty 0.1^decayedCount, song 0.5^decayedCount, neighborhood ×0.6 (sim(candidate,struck)>0.9 ∧ sim(center,struckFrom)>0.8); decay = count × 0.5^(days/30); pool-empty → relax threshold once (−0.1) → playlist-random fallback flagged to UI.
- Weighted RANDOM sampling — never argmax. Deterministic tests inject the RNG (`rng: () => number`).
- All engine/feedback-math code pure TS, zero native imports, fully jest-tested. SQLite access stays in thin adapters.
- Embeddings: Float32Array(200) from existing `embeddingFromBlob`.
- Feedback schema: `feedback_pair(from_id TEXT, rejected_id TEXT, count INTEGER, last_at INTEGER, PRIMARY KEY(from_id,rejected_id))`, `feedback_song(rejected_id TEXT PRIMARY KEY, count INTEGER, last_at INTEGER)` — created by the app on open (CREATE TABLE IF NOT EXISTS) since vibes.db from v1 lacks them.
- No device steps. Verification = `npx tsc --noEmit && npx jest` + `./gradlew assembleRelease` success.
- Work from `app/` unless stated.

### Task 2: FeedbackStore + VibeQueue

**Files:** `feedbackStore.ts`, `vibeQueue.ts`, `vibeQueue.test.ts`.

**Interfaces (locked):**
```typescript
// feedbackStore.ts  (thin adapter; math stays in weights.ts)
export class FeedbackStore {
  constructor(db: DB);                       // op-sqlite handle
  ensureTables(): void;
  recordReject(fromId: string | null, rejectedId: string, nowMs: number): void; // upsert both tables
  snapshot(nowMs: number): FeedbackData;     // reads all rows, pre-decays counts (data is tiny)
}

// vibeQueue.ts
export type VibeMode = 'lock' | 'drift';
export interface VibeQueueDeps {
  songs: VibeSong[];                          // analyzed songs in scope
  feedback: FeedbackData;
  rng?: () => number;
  onFallback?: (kind: 'relaxed' | 'random') => void;
}
export class VibeQueue implements QueueSource {
  constructor(seed: VibeSong, mode: VibeMode, deps: VibeQueueDeps);
  label: string;                              // 'vibe:lock' | 'vibe:drift'
  setMoodFilter(f: {key: string; min: number} | null): void;
  setMode(m: VibeMode): void;
  rejectCurrent(rejectedId: string): void;    // session-ban + caller also hits FeedbackStore
  next(lastPlayed: Song | null): Song | null; // full pipeline: pool→weights→sample; recency from internal history
  reset(seed: Song): void;
}
```
Behavior detail: `next` recenters per mode; maintains play-history for recencyFactor; pool empty → retry once at threshold−0.1 (fire onFallback('relaxed')) → still empty: uniform-random over scope minus bans (fire onFallback('random')); returns null only when scope minus bans is empty. VibeSong→Song mapping needs title/artist: extend VibeSong with `song: Song` payload field (adapt cleanly; keep engine pure).

FeedbackStore: not unit-tested (native) — but `snapshot` pre-decay logic extracted pure and tested if nontrivial.
